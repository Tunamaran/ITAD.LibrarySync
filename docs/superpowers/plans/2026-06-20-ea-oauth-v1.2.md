# EA App Full Library (OAuth + Juno API) — v1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add EA account sign-in so ITAD Library Sync can read the user’s **full online EA library** (e.g. 23 owned titles) even when the encrypted local `IS` cache cannot be decrypted — matching what the EA App UI shows.

**Architecture:** Add a third OAuth stack (EA, separate from ITAD OAuth and Xbox OAuth). After WebView2 login → authorization code → access/refresh tokens, call EA’s **Juno GraphQL** API (`service-aggregation-layer.juno.ea.com`) to fetch `ownedGameProducts`, map `gameSlug` / `originOfferId` to ITAD shop 52 IDs, and merge with the existing v1.1 local readers as fallback. Reuse `OAuthWebViewWindow`, DPAPI token storage, and Settings patterns from Xbox v1.1.

**Tech Stack:** .NET 8, WPF + WebView2, `HttpClient`, DPAPI (`ea-login.dat`), Juno GraphQL over HTTPS.

**Reference implementation (verified 2026-06-20):** [BellezaEmporium/galaxy-integration-ead](https://github.com/BellezaEmporium/galaxy-integration-ead) `juno_api` branch — production-proven against current EA Desktop.

---

## Problem statement (why v1.2 exists)

| Source | What you get | Limitation on user’s PC |
|--------|----------------|-------------------------|
| **v1.1 local `IS` cache** | Full owned list when decrypt works | Fails with hardware-bound encryption (`Padding is invalid`) |
| **Registry / Uninstall fallback** | Installed EA games only | User has 0 installed EA games → 0 results |
| **EA App UI** | Full online library (23 games) | Not accessible to third-party apps without account API |
| **v1.2 Juno OAuth** | Full owned library from EA account | Undocumented API; may break if EA rotates keys |

**Target outcome:** After **Connect EA** in Settings, `Test Read` shows the same owned count as EA App (± filtering rules below). Local cache remains a silent fast-path when it works.

## Honest scope & limitations

| Included in v1.2 | Excluded / deferred |
|------------------|---------------------|
| Owned base games (purchases, redemptions, entitlement grants) | EA wishlist (no stable public API) |
| EA Play titles while entitlement is active | Games hidden via EA privacy settings |
| Deduplication by `gameSlug` (one row per game) | Achievements, friends, playtime |
| Refresh token (~4h JWT, auto-refresh) | Official EA developer/partner registration |
| Merge: OAuth ⊃ local ⊃ registry | macOS EA App |

**Filtering (match galaxy-integration-ead):**

- `type`: `DIGITAL_FULL_GAME`, `PACKAGED_FULL_GAME`
- `ownershipMethod`: `PURCHASE`, `REDEMPTION`, `ENTITLEMENT_GRANT`
- `platforms`: `PC`
- Exclude DLC/expansions (`displayType` addon/expansion, `gameType` extra_content)
- Skip active trials (`trialDetails.trialType` present) unless product is fully owned

**Legal / maintenance note:** Uses reverse-engineered `JUNO_PC_CLIENT` credentials and `pc_sign` hardware attestation (same class of approach as GameCollector’s EA decrypt). Document in README; no EA password is stored — only OAuth tokens in DPAPI files.

## Auth flow (JUNO_PC_CLIENT)

Proven flow from galaxy-integration-ead:

```
1. Generate pc_sign (hardware HMAC payload)
2. WebView2 → GET accounts.ea.com/connect/auth
     ?response_type=code
     &client_id=JUNO_PC_CLIENT
     &display=junoClient/login
     &redirect_uri=qrc:///html/login_successful.html
     &locale=en_US
     &pc_sign={pc_sign}
3. User signs in (2FA possible)
4. Redirect → qrc:///html/login_successful.html?code=...
5. POST accounts.ea.com/connect/token
     grant_type=authorization_code
     client_id=JUNO_PC_CLIENT
     client_secret={embedded}
     redirect_uri=qrc:///html/login_successful.html
     code_verifier={random base64}
     token_format=JWS
     code={code}
6. Store access_token + refresh_token (DPAPI)
7. GET service-aggregation-layer.juno.ea.com/graphql?query={ownedGameProducts...}
     Authorization: Bearer {access_token}
     x-client-id: EAX-JUNO-CLIENT
     referer: https://pc.ea.com/
```

**Fallback auth (Task 3 spike):** If `JUNO_PC_CLIENT` + `pc_sign` fails (EA blocks or key rotation), try `EADOTCOM-WEB-SERVER` with `redirect_uri=https://www.ea.com/login_check` (older web flow, no `pc_sign`). Implement only if primary path fails in manual QA.

## Library API (Juno GraphQL)

**Endpoint:** `https://service-aggregation-layer.juno.ea.com/graphql`

**Identity query:**

```graphql
query { me { player { pd psd displayName } } }
```

**Owned games query** (from galaxy-integration-ead `backend.py`):

```graphql
query getPreloadedOwnedGames(...) {
  me {
    ownedGameProducts(
      storefronts: [EA]
      locale: "DEFAULT"
      paging: { limit: 9999, next: null }
      productFound: true
      orderBy: { field: NAME, direction: ASC }
      ownershipMethod: [PURCHASE, REDEMPTION, ENTITLEMENT_GRANT]
      type: [DIGITAL_FULL_GAME, PACKAGED_FULL_GAME]
      downloadableOnly: false
      entitlementEnabled: true
      platforms: [PC]
    ) {
      items {
        id: originOfferId
        status
        product {
          name
          gameSlug
          downloadable
          trialDetails { trialType }
          baseItem(availabilities: [VISIBLE]) {
            title
            baseGameSlug
            gameType
          }
        }
      }
    }
  }
}
```

**Optional enrichment** (Task 8, if ITAD lookup misses slugs): `legacyOffers` + `gameProducts` batch query by `originOfferId` — defer until slug-only sync proves insufficient.

**Store ID for ITAD:** Prefer `product.baseItem.baseGameSlug` → `product.gameSlug` → `originOfferId` via existing `EaStoreIdResolver`.

## Reader merge strategy (`EaReader` v1.2)

```
ReadAsync():
  if EaOAuthService.HasValidSession():
    try return JunoLibraryReader.ReadOwned()     // primary
    catch auth → prompt reconnect
    catch api   → warning + fall through

  if EaInstallInfoLibraryReader succeeds:       // v1.1 fast path
    return local

  if GameCollector decrypt succeeds:
    return local

  return EaReadResultMerger.MergeRegistryFallback(local error)
```

**Status display:**

| State | DetectionStatus | User action |
|-------|-----------------|-------------|
| OAuth connected, games > 0 | Ready | — |
| OAuth connected, 0 games | Ready | Rare; check filters |
| Not connected, local fails | Error / Limited | Connect EA |
| OAuth + partial local | Ready | Warning: “online library” |

## Risk register

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| EA rotates `client_secret` or `pc_sign` HMAC keys | Medium | Monitor galaxy-integration-ead; centralize constants in `EaOAuthOptions`; spike alerts |
| EA blocks unofficial `JUNO_PC_CLIENT` | Low–Medium | Fallback `EADOTCOM-WEB-SERVER`; document “sign in via EA App + local only” |
| 2FA / CAPTCHA blocks WebView login | Medium | Clear error UI; retry; optional “open in browser” link |
| GraphQL schema/query changes | Medium | Fixture tests fail in CI; pin query version in comment |
| EA Play subscription titles pollute ITAD collection | Low | Filter trials; document that subscription vault games may appear while subscribed |
| ITAD slug mismatch for some EA titles | Medium | Existing `itadlibsync/{slug}` fallback in `EaStoreSyncPayloadPreparer` |
